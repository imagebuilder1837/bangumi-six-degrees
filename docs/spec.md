# 行为规格

领域名称见 [GLOSSARY.md](../GLOSSARY.md)。

## 路径与证明

- 支持无向关联、单向好友、双向好友。返回任意一条跳数最少的路径，不枚举所有等长路径；相同有效端点为零跳，六跳不是上限。
- 使用双向广搜，在整层边界比较预计访问成本选择扩展方向；成本只影响访问顺序，不影响最短性证明。估算可使用旧关系成员数，但估算资料不进入网络模式的证明图。
- 只有候选长度不超过两个搜索方向尚未展开边界的距离之和时，才确认最短；不在首次相遇时无条件结束。某侧完整穷尽可证明不可达。
- 缺少列表是未知，不是空集合。证据不足不展示候选路径；完整证明不可达则明确展示。停止、请求失败和缓存不足均不是不可达。

## 关系观察视图

- 证明相对于本次纳入的、完成必要边界验证的关系观察视图，不承诺统一时刻的全站快照，亦不承诺整个数据库所有记录合并后的全图。缓存不因年龄失效。
- 缓存按观察时间仲裁同一有向关系的正反方向证据；时间相同时优先该边来源用户的 friends 观察。网络模式按本轮观察完成顺序取后一份，不用旧缓存补齐证明。
- 已展开节点受新观察影响时，更新其邻接关系，仅使依赖失效边的父链子树失效，并从受影响边界重新松弛。其他距离、邻接信息和本轮请求结果保留；影响范围可以沿依赖传播。
- 已识别的原站数据错误按无效节点排除；普通 HTTP、网络、身份或结构错误不归入无效节点。仅有昵称“[已注销]”不足以排除用户。
- 整个列表不可访问须严格匹配共享库的专用错误声明条件。合法列表中缺失身份的标准条目只丢弃该条目，保留其他成员；无法将未知身份映射为其他列表中的某个用户。已识别用户条目去重。
- 中间用户采用原站列表链接标识，不额外访问主页归一身份。列表结构或分页无法确认时失败，不以部分列表冒充完整关系。

## 缓存与资料

- 使用 vendor 中的 bangumi-relationship-store；数据库只存关系观察和展示资料，不存搜索状态或路径结果。共享范围受同 origin、浏览器及存储分区限制。
- 每个有效完整方向列表独立入库，不以全次搜索成功为条件。普通请求失败不生成空观察、不覆盖旧记录。写入失败不使网络路径失效；缓存读取失败不自动启动网络搜索。
- 页面首次打开弹窗时，恢复上次成功条件并尝试缓存搜索。之后关闭重开复用当前会话，不重新恢复或搜索；主动探索始终使用网络模式。不提供取数模式开关。
- 头像、昵称从关系列表扫描取得，可随关系存入共享库。缓存模式使用缓存资料；网络搜索的中间用户使用本轮扫描资料，不逐个补抓主页。缺少资料时用用户标识和默认头像。
- 两个端点接受用户标识、数字 ID 或三个 Bangumi 域名的主页链接；用主页身份及规范关系链接归一，不直接拼接数字 ID 的关系子路由。输入失焦及快捷填入时确认身份并更新头像；旧异步结果不得覆盖新输入。

## 请求

- 本组件当前页面内，所有资料和关系请求共用最多四并发的队列，使用同源凭据。
- 单次请求含正文读取的超时为 30 秒。网络、正文读取、408、429、5xx 错误最多重试两次，分别退避一秒、两秒；普通其他 HTTP 错误、跳转和解析错误不重试。
- 429 的 Retry-After 约束所有后续新请求与重试，取全局截止时间与当前退避要求的较大者。缺少有效值时等待 60 秒；429 仍计入重试次数。
- 停止须使排队、退避、请求和正文读取及时结束，即使底层传输不响应取消。已经提交的缓存不回滚；旧任务收尾不得覆盖新任务。

## 交互

- 仅在三个域名的好友及反向好友页挂载一个固定右下入口；使用静态、灵动的关系节点 logo，不承担运行或完成通知。
- 弹窗桌面顶部为两个端点，中间是关系模式及对应无向、单向、双向连线，下方可交换端点；窄屏上下排列。每个端点提供填入自己、填入主页用户；无法识别登录用户时禁用前者。
- 修改端点、交换或切换模式不自动搜索；旧结果须明确属于旧条件。运行时锁定条件，保留停止能力。关闭只隐藏，搜索继续；重开复用，完成不自动弹窗。
- 中部展示状态和最终路径；长路径横向滚动，用户节点可打开主页。不给搜索编造百分比，不展示未证明的当前候选。超过六跳显示轻量彩蛋。
- 探索和停止按钮放右下角；原站粉色基调、明暗主题、窄屏布局、键盘关闭及焦点约束均适配。减少动态效果偏好下禁用动画。
- 只在找到已证明最短的路径后，将两个规范 username 和关系模式记入 localStorage，不保存路径副本。零跳也成功；不可达、失败、停止不覆盖记忆。下次打开仍须重新用缓存证明；无记录时两端为空、默认无向关联。
